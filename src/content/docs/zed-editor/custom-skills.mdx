## Overview

Custom skills allow you to create specialized AI assistance tailored to your specific projects, coding patterns, and workflows in Zed. Skills extend AgentLoop's capabilities with domain-specific knowledge and context-aware behaviors.

## Skill Basics

### What is a Skill?

A skill is a specialized instruction set that:
- Triggers based on keywords or context
- Provides domain-specific knowledge
- Follows project conventions
- Includes relevant examples and patterns

### Skill Structure

Skills are Markdown files with YAML frontmatter:

```markdown
---
name: skill-name
description: Brief description of what this skill does  
triggers:
  - "keyword1"
  - "phrase to trigger"
  - "pattern"
context_types:
  - "rust"
  - "typescript"
project_types:
  - "web-api"
  - "cli-tool"
---

# Skill Instructions

Detailed instructions for the AI agent...
```

# Rust Web API Development with Axum

When working with Rust web APIs using Axum framework:

## Architecture Patterns

1. **Handler Functions**: Use async functions that return `Result<impl IntoResponse, AppError>`
2. **State Management**: Use `axum::extract::State` for shared application state
3. **Error Handling**: Create custom error types that implement `IntoResponse`
4. **Validation**: Use serde for request/response serialization with validation

## Code Templates

### Basic Handler Pattern
```rust
use axum::{extract::State, http::StatusCode, response::Json, Result};

pub async fn create_user(
    State(app_state): State<AppState>,
    Json(payload): Json<CreateUserRequest>,
) -> Result<Json<User>, AppError> {
    // Validation
    payload.validate()?;
    
    // Business logic
    let user = app_state.user_service.create(payload).await?;
    
    Ok(Json(user))
}
```

### Error Handling Pattern
```rust
#[derive(Debug, thiserror::Error)]
pub enum AppError {
    #[error("Database error: {0}")]
    Database(#[from] sqlx::Error),
    
    #[error("Validation error: {0}")]
    Validation(String),
}

impl IntoResponse for AppError {
    fn into_response(self) -> Response {
        let (status, message) = match self {
            AppError::Database(_) => (StatusCode::INTERNAL_SERVER_ERROR, "Database error"),
            AppError::Validation(msg) => (StatusCode::BAD_REQUEST, &msg),
        };
        
        (status, Json(ErrorResponse { error: message.to_string() })).into_response()
    }
}
```

## Best Practices

1. **Use extractors properly**: Path, Query, Json, State in correct order
2. **Implement proper error handling**: Custom error types with IntoResponse
3. **Add request validation**: Use serde with validator crate
4. **Structure responses consistently**: Standard success/error formats
5. **Add proper logging**: Use tracing for structured logging
6. **Test endpoints thoroughly**: Unit tests for handlers and integration tests

## Testing Patterns

Always include:
- Success case tests
- Validation error tests  
- Database error handling tests
- Authentication/authorization tests

## Component Patterns

### Functional Component with Props
```tsx
interface UserCardProps {
  user: User;
  onClick?: (userId: string) => void;
  className?: string;
}

export const UserCard: React.FC<UserCardProps> = ({ 
  user, 
  onClick, 
  className 
}) => {
  const handleClick = useCallback(() => {
    onClick?.(user.id);
  }, [onClick, user.id]);

  return (
    <div className={cn("user-card", className)} onClick={handleClick}>
      <h3>{user.name}</h3>
      <p>{user.email}</p>
    </div>
  );
};
```

### Custom Hook Pattern
```tsx
interface UseUserDataReturn {
  users: User[];
  loading: boolean;
  error: string | null;
  refetch: () => void;
}

export const useUserData = (): UseUserDataReturn => {
  const [users, setUsers] = useState<User[]>([]);
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState<string | null>(null);

  const fetchUsers = useCallback(async () => {
    try {
      setLoading(true);
      const response = await userAPI.getUsers();
      setUsers(response);
      setError(null);
    } catch (err) {
      setError(err instanceof Error ? err.message : 'Unknown error');
    } finally {
      setLoading(false);
    }
  }, []);

  useEffect(() => {
    fetchUsers();
  }, [fetchUsers]);

  return { users, loading, error, refetch: fetchUsers };
};
```

## Conventions

1. **Props Interface**: Always define props interface with proper typing
2. **Event Handlers**: Use `useCallback` for event handlers to prevent re-renders
3. **State Management**: Use appropriate state patterns (useState, useReducer, context)
4. **Error Handling**: Implement proper error boundaries and error states
5. **Performance**: Use React.memo, useMemo, useCallback appropriately
6. **Testing**: Write tests with React Testing Library

# Database Schema Design

## Design Principles

1. **Normalization**: Follow 3NF unless performance requires denormalization
2. **Indexing**: Add indexes for frequently queried columns
3. **Constraints**: Use appropriate constraints for data integrity
4. **Naming**: Consistent naming conventions (snake_case for PostgreSQL)

## Common Patterns

### User Management Schema
```sql
-- Users table
CREATE TABLE users (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    email VARCHAR(255) UNIQUE NOT NULL,
    username VARCHAR(50) UNIQUE NOT NULL,
    password_hash VARCHAR(255) NOT NULL,
    first_name VARCHAR(100),
    last_name VARCHAR(100),
    is_active BOOLEAN DEFAULT true,
    email_verified BOOLEAN DEFAULT false,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
    updated_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

-- User roles (many-to-many)
CREATE TABLE user_roles (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    role_name VARCHAR(50) NOT NULL,
    granted_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
    granted_by UUID REFERENCES users(id),
    UNIQUE(user_id, role_name)
);

-- Indexes
CREATE INDEX idx_users_email ON users(email);
CREATE INDEX idx_users_username ON users(username);
CREATE INDEX idx_user_roles_user_id ON user_roles(user_id);
CREATE INDEX idx_users_created_at ON users(created_at);
```

### Audit Log Pattern
```sql
CREATE TABLE audit_logs (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    table_name VARCHAR(100) NOT NULL,
    operation VARCHAR(10) NOT NULL, -- INSERT, UPDATE, DELETE
    old_values JSONB,
    new_values JSONB,
    changed_by UUID REFERENCES users(id),
    changed_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

CREATE INDEX idx_audit_logs_table_name ON audit_logs(table_name);
CREATE INDEX idx_audit_logs_changed_at ON audit_logs(changed_at);
CREATE INDEX idx_audit_logs_changed_by ON audit_logs(changed_by);
```

## Migration Best Practices

1. **Backward Compatibility**: Ensure migrations don't break existing code
2. **Rollback Plan**: Always have a rollback strategy
3. **Data Migration**: Separate schema and data migrations
4. **Testing**: Test migrations on production-like data
5. **Performance**: Consider impact on large tables

## Rust Integration (sqlx)
```rust
// User model
#[derive(sqlx::FromRow, Serialize, Deserialize)]
pub struct User {
    pub id: Uuid,
    pub email: String,
    pub username: String,
    #[serde(skip)]
    pub password_hash: String,
    pub first_name: Option<String>,
    pub last_name: Option<String>,
    pub is_active: bool,
    pub email_verified: bool,
    pub created_at: chrono::DateTime<chrono::Utc>,
    pub updated_at: chrono::DateTime<chrono::Utc>,
}

// Repository pattern
impl UserRepository {
    pub async fn create(&self, user: CreateUserRequest) -> Result<User, DbError> {
        let user = sqlx::query_as!(
            User,
            r#"
            INSERT INTO users (email, username, password_hash, first_name, last_name)
            VALUES ($1, $2, $3, $4, $5)
            RETURNING *
            "#,
            user.email,
            user.username,
            user.password_hash,
            user.first_name,
            user.last_name
        )
        .fetch_one(&self.pool)
        .await?;

        Ok(user)
    }
}
