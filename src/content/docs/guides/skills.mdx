## What Are Skills?

Skills are on-demand instruction sets that AgentLoop provides to the main agent when it needs specialized guidance. Instead of bloating every prompt with specialized instructions, a lightweight **SkillAgent** selects the most relevant skill at runtime when the main agent requests one via the `Find_skill` tool.

## Creating a Skill

### Step 1: Create the Skill Directory

```bash
mkdir -p ~/.local/share/agentloop/vault/skills/code-review
```

### Step 2: Write SKILL.md

Create `~/.local/share/agentloop/vault/skills/code-review/SKILL.md`:

```markdown
---
name: code-review
description: Code review best practices and checklist
tags:
  - review
  - PR
  - pull request
  - code review
---

# Code Review

When reviewing code, follow this checklist:

1. **Correctness** — Does the code do what it claims?
2. **Security** — Are there injection risks, auth issues, or data leaks?
3. **Performance** — Any N+1 queries, unnecessary allocations, or missing indexes?
4. **Readability** — Is the code clear without excessive comments?
5. **Tests** — Are edge cases covered? Are tests meaningful, not just present?
6. **Error handling** — Are errors handled gracefully? No swallowed errors?

When providing feedback:
- Be specific — reference line numbers and file paths
- Explain WHY something is an issue, not just WHAT
- Suggest concrete fixes, not just criticism
- Prioritize: blockers first, then suggestions, then nits
```

### Step 3: Restart the Server

Skills are loaded on server startup:

```bash
pm2 restart agentloop-server
```

### Step 4: Test

Run a task that mentions code review:

```bash
./agentloop "review the changes in src/auth.go"
```

When the main agent determines it needs review guidance, it calls `Find_skill`. The SkillAgent evaluates the skill catalog and selects `code-review` based on its description and tags. The skill's full instructions and any sibling files are returned to the main agent.

## How Skill Selection Works

AgentLoop uses **LLM-driven skill selection** — no lexical keyword matching.

### The `Find_skill` Tool

When the main agent needs specialized guidance, it calls `Find_skill` with a natural-language query describing what it needs (e.g., `"I need code review best practices"`).

### The SkillAgent

A short-lived subprocess receives the query along with the **skill catalog** — a compact list of every registered skill's `name`, `description`, and `tags`. The SkillAgent reasons over this catalog and returns the **single best matching skill**, or `"none"` if no skill is relevant.

### Selection Flow

1. Main agent calls `Find_skill` with a descriptive query
2. SkillAgent receives the query + skill catalog (name, description, tags for all skills)
3. SkillAgent picks the single most relevant skill (or `"none"`)
4. The selected skill's full details (instructions, files, directory path) are returned to the main agent

<Aside type="tip">
  Tags are semantic hints, not lexical triggers. A well-written `description` is the primary signal the SkillAgent uses. Tags provide additional context (e.g., related technologies or use cases).
</Aside>

## SKILL.md Format

```markdown
---
name: skill-name          # Required (defaults to directory name if absent)
description: What it does  # Primary signal for LLM-driven selection
tags:                      # Optional — semantic hints for the SkillAgent
  - keyword1
  - keyword2
---

Markdown instructions here...
```

- **name** — Unique identifier for the skill
- **description** — Human-readable description; the primary signal the SkillAgent uses to evaluate relevance
- **tags** — Optional array of semantic hints that help the SkillAgent match the skill to a query
- **Body** — Everything after the second `---` delimiter, written in markdown

## Sibling Files

Any non-hidden files placed alongside `SKILL.md` in the skill directory are automatically discovered and returned with the skill when selected. This lets you bundle scripts, templates, or config files with a skill.

```
~/.local/share/agentloop/vault/skills/deploy/
├── SKILL.md
├── deploy.sh
└── config.yaml
```

## Skill Directories

Skills are loaded from all directories listed in `skills.skill_dirs` config:

```yaml
skills:
  skill_dirs:
    - ~/.local/share/agentloop/vault/skills
    - ~/my-custom-skills
```

<Aside type="tip">
  Skills are loaded on server startup. After adding or modifying a skill, restart the server for changes to take effect.
</Aside>

## Verifying Skill Loading

Check server startup logs for skill names:

```bash
pm2 logs agentloop-server --lines 20
```

You should see log entries indicating which skills were loaded.
