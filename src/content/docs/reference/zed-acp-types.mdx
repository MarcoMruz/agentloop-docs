## Overview

This reference documents the Rust types used in the AgentLoop Zed ACP integration. All types are defined in the `agentloop-bridge` crate with the `zed-acp` feature enabled.

## Core ACP Types

### ACPMessage

```rust
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct ACPMessage {
    pub id: String,
    pub method: ACPMethod,
    pub params: serde_json::Value,
    pub timestamp: chrono::DateTime<chrono::Utc>,
}

#[derive(Debug, Clone, Serialize, Deserialize)]
#[serde(tag = "type", rename_all = "snake_case")]
pub enum ACPMethod {
    Initialize(InitializeParams),
    Request(RequestParams),
    Context(ContextParams),
    Response(ResponseParams),
    Error(ErrorParams),
}
```

### Bridge Implementation Types

```rust
#[derive(Debug)]
pub struct ZedBridge {
    socket_path: PathBuf,
    connection: Option<UnixStream>,
    event_sender: mpsc::UnboundedSender<StreamEvent>,
    config: ZedConfig,
    active_sessions: HashMap<String, SessionInfo>,
}

#[derive(Debug, Clone)]
pub struct SessionInfo {
    pub id: String,
    pub user_id: String,
    pub created_at: chrono::DateTime<chrono::Utc>,
    pub last_activity: chrono::DateTime<chrono::Utc>,
    pub context: ZedContext,
    pub model: String,
}

impl ZedBridge {
    pub fn new(config: ZedConfig) -> Result<Self, BridgeError>;
    pub async fn connect(&mut self) -> Result<(), BridgeError>;
    pub async fn disconnect(&mut self) -> Result<(), BridgeError>;
    
    pub async fn send_request(
        &mut self,
        request: RequestParams
    ) -> Result<String, BridgeError>; // Returns session_id
    
    pub async fn stream_events(
        &self
    ) -> Result<mpsc::UnboundedReceiver<StreamEvent>, BridgeError>;
    
    pub async fn respond_hitl(
        &mut self,
        session_id: &str,
        request_id: &str,
        decision: HITLDecision
    ) -> Result<(), BridgeError>;
}

#[derive(Debug, Clone, Serialize, Deserialize)]
#[serde(rename_all = "lowercase")]
pub enum HITLDecision {
    Approve,
    Deny,
    Abort,
}
```

## Usage Examples

### Basic Request

```rust
use agentloop_bridge::zed::{ZedBridge, RequestParams, ZedContext};

#[tokio::main]
async fn main() -> Result<(), Box<dyn std::error::Error>> {
    let config = ZedConfig::default();
    let mut bridge = ZedBridge::new(config)?;
    bridge.connect().await?;

    let context = ZedContext {
        file: extract_file_context(&current_file, cursor_pos, 50)?,
        selection: Some(extract_selection_context(&content, start, end, 10)),
        project: extract_project_context(&workspace_root, &config)?,
        diagnostics: extract_diagnostics(&current_file),
        git: extract_git_context(&workspace_root)?,
    };

    let request = RequestParams {
        user_id: "zed-user".to_string(),
        message: "Explain this function".to_string(),
        context,
        session_id: None,
        model_preferences: None,
    };

    let session_id = bridge.send_request(request).await?;
    println!("Started session: {}", session_id);

    Ok(())
}
```

### Event Streaming

```rust
let mut event_stream = bridge.stream_events().await?;

while let Some(event) = event_stream.recv().await {
    match event.event_type {
        StreamEventType::TextDelta => {
            let delta: TextDelta = serde_json::from_value(event.data)?;
            print!("{}", delta.content);
        }
        StreamEventType::HITLRequest => {
            let hitl: HITLRequest = serde_json::from_value(event.data)?;
            let decision = prompt_user(&hitl)?;
            bridge.respond_hitl(&event.session_id, &hitl.request_id, decision).await?;
        }
        StreamEventType::Complete => {
            println!("\nTask completed!");
            break;
        }
        StreamEventType::Error => {
            eprintln!("Error: {:?}", event.data);
            break;
        }
        _ => {}
    }
}
```

## Key Implementation Notes

1. **Async by Design**: All I/O operations are async using Tokio
2. **Type Safety**: Extensive use of Rust's type system for correctness
3. **Memory Efficiency**: Zero-copy deserialization where possible
4. **Error Handling**: Comprehensive error types with context
5. **Security**: Built-in validation and sanitization
6. **Performance**: Lazy loading and caching of context data
7. **Compatibility**: Full JSON-RPC 2.0 compliance for wire protocol
