## JSON-RPC Methods

### `memory.get`

Get the assembled memory context for a user.

**Params:** `{ userId: string }`

**Result:** `{ context: string }`

The returned context is the fully assembled prompt prefix including profile, relevant history, and memory notes.

### `memory.update`

Set or update a user fact in the profile's fact sheet.

**Params:** `{ userId: string, key: string, value: string }`

**Result:** `{ ok: true }`

**Side effects:** Invalidates the prompt cache for this user.

### `memory.forget`

Remove a user fact from the profile's fact sheet.

**Params:** `{ userId: string, key: string }`

**Result:** `{ ok: true }`

**Side effects:** Invalidates the prompt cache for this user.

## Go Engine Public Methods

### `GetContextForUser(userId string) (string, error)`

Assembles full memory context from profile and last 30 conversation entries. Used for non-task contexts (e.g. thread-scoped retrieval fallback).

1. Check prompt cache → return if hit
2. Load user profile from `ProfileStore`
3. Load recent conversation entries from `ConversationStore`
4. Compact if over threshold
5. Assemble context string
6. Cache with 5-minute TTL
7. Return

### `GetContextForUserWithTask(userId, task string) (string, error)`

Task-aware context assembly with MemScheduler routing:

1. **MemScheduler** — call `Schedule(task)` to determine context level (Minimal / Standard / Detailed)
2. **Minimal** — return profile + top-3 keyword-matched notes; skip history entirely
3. **Standard / Detailed** — delegate to MemEvolve pipeline if configured; otherwise:
   - Extract keywords and topics from task text
   - Score each conversation entry by keyword overlap (Jaccard similarity) + topic bonus (+0.2)
   - Return top 8 entries (Standard) or top 16 entries (Detailed), or 5 most recent if no matches found
   - Augment with notes: vector search (if embeddings available), then keyword search; deduplicate

### `RecordInteraction(userId, userMsg, agentReply string, toolsUsed []string, conversationContextID string)`

Save a conversation turn and update the user profile.

**Side effects:**
- Appends entry to today's conversation log
- Updates conversation index (keywords, topics, summary)
- Runs heuristic profile updates (project paths, topics, tool usage)
- If `LLMClient` is set: asynchronously extracts one atomic note (ACE delta) from the conversation
- Invalidates prompt cache

### `AddNote(note notes.AtomicNote) (string, error)`

Persist an atomic note, invalidate the user's context cache, and auto-link to the top-3 keyword-related existing notes.

**Returns:** assigned note ID.

### `UpdateNote(note notes.AtomicNote) error`

Update an existing atomic note and invalidate the user's context cache.

### `DeleteNote(userID, noteID string) error`

Remove an atomic note by ID and invalidate the user's context cache.

### `SetNoteStore(s notes.NoteStore)`

Wire in an atomic notes store. Must be called before the engine handles requests.

### `SetLLMClient(c llm.LLMClient)`

Wire in the background LLM client used for embeddings and ACE delta extraction.

### `UpdateUserFact(userId, key, value string) error`

Set a fact in the user's profile fact sheet.

**Side effects:** Invalidates prompt cache.

### `ForgetUserFact(userId, key string) error`

Remove a fact from the user's profile fact sheet.

**Side effects:** Invalidates prompt cache.

## AtomicNote Schema

Stored in per-user SQLite databases at `vault/memory/notes/<userId>.db`:

```go
type AtomicNote struct {
    ID          string    `json:"id"`           // format: note-XXXXXXXX
    UserID      string    `json:"user_id"`
    Content     string    `json:"content"`      // the single atomic fact
    Keywords    []string  `json:"keywords"`     // 3-7 lowercase terms
    Tags        []string  `json:"tags"`         // e.g. "preference", "tool", "project", "workflow"
    Description string    `json:"description"`
    Embedding   []float32 `json:"embedding,omitempty"` // set when memory.agent.enabled: true
    Connections []string  `json:"connections"`  // IDs of auto-linked related notes
    CreatedAt   time.Time `json:"created_at"`
    UpdatedAt   time.Time `json:"updated_at"`
}
```

| Field | Description |
|-------|-------------|
| `ID` | Assigned on insert; format `note-XXXXXXXX` |
| `Keywords` | Used for Jaccard keyword search |
| `Tags` | Category labels for filtering |
| `Embedding` | Dense vector for cosine similarity search; populated when `memory.agent.enabled: true` and `memory.embedding_dims > 0` |
| `Connections` | Bidirectional links to related notes; populated automatically on `AddNote()` |

## UserProfile Schema

Stored as YAML in `vault/memory/users/<userId>.yaml`:

```go
type UserProfile struct {
    UserID             string            `yaml:"userid"`
    Name               string            `yaml:"name"`
    CommunicationStyle string            `yaml:"communicationstyle"`
    Preferences        map[string]string `yaml:"preferences"`
    FrequentProjects   []string          `yaml:"frequentprojects"`
    ToolPreferences    []string          `yaml:"toolpreferences"`
    FactSheet          map[string]string `yaml:"factsheet"`
    RecentTopics       []string          `yaml:"recenttopics"`
    LastUpdated        string            `yaml:"lastupdated"`
}
```

| Field | Type | Max Size | Description |
|-------|------|----------|-------------|
| `UserID` | string | — | User identifier |
| `Name` | string | — | Display name |
| `CommunicationStyle` | string | — | Default: `"concise, technical"` |
| `Preferences` | map[string]string | — | Key-value preferences |
| `FrequentProjects` | []string | 10 | Most recently used project paths |
| `ToolPreferences` | []string | — | Tools the user commonly uses |
| `FactSheet` | map[string]string | — | Explicit user facts (set via `memory.update`) |
| `RecentTopics` | []string | 20 | Most recent conversation topics |
| `LastUpdated` | string | — | RFC3339 timestamp |

## Conversation Log Format

**File:** `vault/memory/contexts/<userId>-YYYY-MM-DD.md`

```markdown
### 14:00:00 [user]
Fix the failing tests in user.go

### 14:00:05 [assistant]
I'll look at the test files and identify the failures...
```

**Index sidecar:** `vault/memory/contexts/<userId>-YYYY-MM-DD.idx.json`

```json
[
  {
    "ts": "14:00:00",
    "role": "user",
    "keywords": ["failing", "tests", "user"],
    "topics": ["test"],
    "summary": "Fix the failing tests in user.go"
  }
]
```

- Up to 15 keywords per entry (4+ char words, 90+ stopwords filtered)
- Summary: first 120 chars from first non-header line

## Compaction Algorithms

Compaction is a **no-op** when raw history already fits within the token budget — the original text is returned unchanged. The budget passed to the compactor is `max_context_tokens − profile tokens`, with a minimum of 200 tokens. Token count is estimated as `len(text) / 4`.

When the budget is exceeded, the selected strategy runs. History is split into turns on `### ` markers before any strategy is applied.

### Rolling (default)

Keeps the last 5 turns verbatim. For each older turn, extracts the first non-header, non-empty line and truncates it to 100 chars.

Output format:

```
**Earlier (summarized):**
- <first meaningful line of older turn, ≤100 chars>
...

**Recent:**
### <full turn>
...
```

If the combined output still exceeds the token budget it is trimmed from the front.

### Facts

Scans every line across all history for signal keywords and structural markers. A line is kept if it contains any of:

`decided`, `confirmed`, `created`, `fixed`, `deployed`, `merged`, `installed`, `configured`, `updated`, `deleted`, `error`, `failed`

or if it starts with `- ` (bullet) or `Tools:` (tool call record).

Each kept line is truncated to 150 chars. Only the 30 most recent matching lines are retained.

Output format:

```
**Key facts:**
<matching line>
...
```

### Topics

Splits history into turns on `### ` markers. Derives a topic key from the first 3 words of each turn (lowercased). When multiple turns share the same topic key, only the most recent is kept.

Output: deduplicated turns joined by newline, no topic headers added.

## Prompt Cache

- **Storage:** In-memory (not persisted)
- **Key format:** `ctx:<userId>` or `ctx:<userId>:<taskCacheKey>`
- **TTL:** 5 minutes (hardcoded)
- **Invalidation triggers:** `RecordInteraction()`, `UpdateUserFact()`, `ForgetUserFact()`, `AddNote()`, `UpdateNote()`, `DeleteNote()`
- **Task cache key:** Normalized task text, max 32 chars, special chars replaced with `-`
