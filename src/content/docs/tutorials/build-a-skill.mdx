## Goal

Create a **git-helper** skill that provides Git workflow guidance when the agent needs help with Git operations.

## Step 1: Create the Skill Directory

```bash
mkdir -p ~/.local/share/agentloop/vault/skills/git-helper
```

## Step 2: Write SKILL.md

Create `~/.local/share/agentloop/vault/skills/git-helper/SKILL.md`:

```markdown
---
name: git-helper
description: Git workflow best practices and conventional commits
tags:
  - git
  - commit
  - branch
  - merge
  - rebase
---

# Git Helper

When working with Git, follow these conventions:
- Use conventional commits: feat:, fix:, docs:, refactor:, test:, chore:
- Create feature branches from main: `git checkout -b feat/description`
- Squash commits before merging
- Write meaningful commit messages explaining WHY, not just WHAT
- Always run tests before committing
- Use `git status` and `git diff` before staging
- Prefer `git add -p` for selective staging over `git add .`
```

### Frontmatter Breakdown

- **`name: git-helper`** — Unique identifier, shown in logs
- **`description`** — Human-readable; the primary signal the SkillAgent uses to evaluate relevance
- **`tags`** — Semantic hints that help the SkillAgent match this skill to a query

<Aside type="tip">
  `tags` are optional. A well-written `description` is often the most important factor for selection — the SkillAgent reasons over descriptions and tags together to pick the best skill.
</Aside>

## Step 3: Restart the Server

Skills are loaded on server startup:

```bash
pm2 restart agentloop-server
```

Check the logs to confirm the skill was loaded:

```bash
pm2 logs agentloop-server --lines 10
```

You should see a log entry indicating the `git-helper` skill was registered.

## Step 4: Test

Run a task that involves Git:

```bash
./agentloop "create a feature branch for the login page"
```

When the main agent determines it needs Git guidance, it calls `Find_skill` with a query like `"Git branching conventions"`. The SkillAgent evaluates the skill catalog and selects `git-helper` based on its description and tags. The skill's instructions are then available to the agent.

## Step 5: Verify

The agent should follow the conventions from the skill:

```bash
# Expected behavior:
# - Creates branch with "feat/" prefix
# - Uses conventional naming
# - Follows the skill's instructions
```

## How It Works

AgentLoop uses **LLM-driven skill selection** instead of lexical keyword matching:

1. The main agent encounters a task where it needs specialized guidance
2. It calls the `Find_skill` tool with a natural-language query (e.g., `"I need help with Git branching"`)
3. A lightweight **SkillAgent** subprocess receives the query along with the **skill catalog** — a compact list of every registered skill's `name`, `description`, and `tags`
4. The SkillAgent reasons over the catalog and returns the **single best matching skill** (or `"none"`)
5. The selected skill's full details (instructions, sibling files, directory path) are returned to the main agent

<Aside type="tip">
  Write a clear, specific `description` — it's the primary signal. Use `tags` to provide additional semantic context like related technologies or use cases.
</Aside>
