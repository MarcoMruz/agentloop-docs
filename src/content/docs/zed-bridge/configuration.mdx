## Bridge Configuration

The `agentloop-acp-bridge` binary itself has no config file — it reads two CLI arguments and inherits the rest from the AgentLoop server config:

| CLI Argument | Default | Description |
|---|---|---|
| `--socket-path` | `~/.local/share/agentloop/agentloop.sock` | Unix socket path |
| `--path-map` | — | `LOCAL:REMOTE` path translation for remote servers |

Everything else (memory, sessions, HITL, security, skills) is controlled by `~/.config/agentloop/agentloop.yaml` on the server.

## Server Config Fields Relevant to Zed

### `server.socket_path`

Path to the Unix domain socket. Must match `--socket-path` in the Zed `settings.json`:

```yaml
server:
  socket_path: ~/.local/share/agentloop/agentloop.sock
```

### `sessions`

Controls the lifetime and resource limits of AgentLoop sessions (each Zed prompt turn starts one):

```yaml
sessions:
  max_concurrent: 5          # Maximum simultaneous AgentLoop sessions
  max_per_user: 3            # Maximum sessions per user ID
  timeout_seconds: 300       # Idle session timeout
  token_budget: 100000       # Max tokens per session
  tool_call_limit: 50        # Max tool calls per session
  stuck_threshold: 30        # Seconds before session is considered stuck
  evict_lru: true            # Evict oldest session when max_concurrent is reached
```

<Aside type="note">
  Each Zed Agent panel prompt starts a new AgentLoop session. Multi-turn conversation is stitched together by the bridge using conversation history injected into the task text — the underlying AgentLoop sessions are not shared across turns.
</Aside>

### `hitl`

Controls HITL approval gates triggered during Zed sessions:

```yaml
hitl:
  timeout_seconds: 300       # Auto-deny after this many seconds
  timeout_action: deny       # "deny" or "abort"
  always_pause_tools:        # Force HITL for these tool names
    - bash
```

### `security`

Path restrictions and injection protection for files accessed via Zed:

```yaml
security:
  allowed_paths:
    - ~/dev
    - ~/projects
  blocked_env_prefixes:
    - ANTHROPIC_
    - OPENAI_
    - AWS_
  injection:
    enabled: true
    whitelist_sources:
      - ~/dev/trusted
    blocked_keywords: []
    require_approval: []
    max_content_length: 50000
    approval_tier: owner      # "owner", "admin", or "auto-deny"
    sanitize_memory: true
```

### `pi`

Controls the pi subprocess that runs inside each AgentLoop session:

```yaml
pi:
  binary: pi
  provider: anthropic
  model: claude-sonnet-4-20250514
  extensions_dir: /home/marco/dev/agentloop/extensions
  extra_args: []
```

The `source` field sent by the bridge is `"zed-acp"` — this appears in vault session files as the `source` frontmatter field, useful for filtering Zed-originated sessions in Obsidian.

### `memory`

Memory depth affects how much context AgentLoop injects into each Zed session:

```yaml
memory:
  profile_entries_limit: 20
  conversation_retention_days: 30
  cache_ttl_seconds: 300
  embedding_dims: 0           # Set to > 0 to enable vector search
  agent:
    enabled: false            # Enable for async delta extraction (uses cheap model)
    provider: anthropic
    model: claude-haiku-4-20250514
```

### `logging`

Bridge logs go to stderr (captured by Zed). Server logs are configured here:

```yaml
logging:
  level: info                 # debug, info, warn, error
  file: ~/.local/share/agentloop/agentloop.log
```

To see bridge-level debug output, set the `RUST_LOG` environment variable in Zed's `settings.json`:

```json
{
  "agent_servers": {
    "AgentLoop": {
      "type": "custom",
      "command": "agentloop-acp-bridge",
      "args": ["--socket-path", "~/.local/share/agentloop/agentloop.sock"],
      "env": {
        "RUST_LOG": "agentloop=debug,agentloop_bridge=debug"
      }
    }
  }
}
```

## Session Vault Paths

Sessions started from Zed are persisted to the vault alongside CLI and Slack sessions:

```
~/.local/share/agentloop/vault/
└── sessions/
    └── YYYY-MM-DD-sess-{uuid8}.md
```

Each session file includes a `source: zed-acp` frontmatter field, making it easy to filter Zed sessions in Obsidian or with `grep`:

```bash
grep -l "source: zed-acp" ~/.local/share/agentloop/vault/sessions/
```

## Full Minimal Config

Minimum `agentloop.yaml` to use with the Zed bridge:

```yaml
server:
  socket_path: ~/.local/share/agentloop/agentloop.sock

pi:
  provider: anthropic
  model: claude-sonnet-4-20250514

security:
  allowed_paths:
    - ~/dev

sessions:
  max_concurrent: 5
  timeout_seconds: 300

hitl:
  timeout_seconds: 300
  timeout_action: deny

logging:
  level: info
```

<Aside type="tip">
  If `~/.config/agentloop/agentloop.yaml` does not exist, the server starts with built-in defaults. The defaults include a 300-second session timeout, `max_concurrent: 10`, and no path restrictions — suitable for local development but too permissive for production.
</Aside>
