## `AgentLoopClient`

```ts
import { AgentLoopClient, loadConfig } from "./agentloop-client.js";

const config = loadConfig(); // or loadConfig("/custom/path.sock")
const client = new AgentLoopClient(config);
await client.connect();
```

Extends `EventEmitter`. Creates a new socket connection per use (connect → startTask → stream events → close).

---

### `loadConfig(socketPathOverride?)`

```ts
function loadConfig(socketPathOverride?: string): AgentLoopConfig
```

Reads server settings from `~/.config/agentloop/agentloop.yaml`. Falls back to defaults if the file is absent or the key is missing. Pass `socketPathOverride` to ignore the config file's socket path.

Returns an `AgentLoopConfig`:

```ts
interface AgentLoopConfig {
  socketPath: string;   // default: ~/.local/share/agentloop/agentloop.sock
  requestTimeout: number; // default: 30000 ms
}
```

`~/` in `socketPathOverride` is expanded automatically.

---

### Constructor

```ts
new AgentLoopClient(config: AgentLoopConfig)
```

| Parameter | Type | Description |
|---|---|---|
| `config` | `AgentLoopConfig` | Socket path and timeout settings |

### Methods

#### `connect(): Promise<void>`

Opens the Unix socket connection. Resolves when the socket is ready, rejects on error. Call this before any other method.

#### `close(): Promise<void>`

Closes the connection: rejects all pending requests with `"Connection closed"`, destroys the readline interface, and destroys the socket.

#### `startTask(userId, text, workDir, source): Promise<string>`

Sends `task.start` to the server and returns the assigned AgentLoop session ID.

```ts
const alSessionId = await client.startTask(
  process.env.USER || "user",  // userId
  fullPrompt,                   // text — full conversation prompt
  state.cwd,                    // workDir — project root
  "zed-acp"                     // source label stored in vault
);
// alSessionId: "sess-xxxxxxxx"
```

| Parameter | Type | Description |
|---|---|---|
| `userId` | `string` | AgentLoop user ID (memory + session routing) |
| `text` | `string` | Task description or full conversation prompt |
| `workDir` | `string \| undefined` | Working directory for the agent subprocess |
| `source` | `string` | Source label stored in the session vault entry |

Returns a `string` — the AgentLoop session ID (e.g. `"sess-a1b2c3d4"`).

#### `abortTask(sessionId): Promise<void>`

Sends `task.abort`. Stops the running task; the session transitions to `aborted`.

```ts
await client.abortTask(alSessionId);
```

#### `respondHitl(sessionId, requestId, decision): Promise<void>`

Sends the user's HITL decision to the server.

```ts
await client.respondHitl(alSessionId, event.requestId, decision);
```

| Parameter | Type | Values |
|---|---|---|
| `sessionId` | `string` | AgentLoop session ID |
| `requestId` | `string` | `event.requestId` from the `hitl_request` event |
| `decision` | `HITLDecision` | `"approve"` \| `"deny"` \| `"abort"` |

#### `healthCheck(): Promise<unknown>`

Sends `health.check` and returns the raw result object (`{ status: "ok", activeSessions: number }`).

## `AgentEvent` Type

All server notifications are parsed into a single `AgentEvent` object emitted on the `"event"` channel. Use the `type` field as the discriminator.

```ts
interface AgentEvent {
  type: "text" | "tool_use" | "tool_result" | "hitl_request"
      | "hitl_auto_approved" | "done" | "error" | "session_saved";
  sessionId: string;

  // type: "text"
  content?: string;

  // type: "tool_use"
  toolName?: string;
  input?: unknown;

  // type: "tool_result"
  // toolName, plus:
  output?: string;
  success?: boolean;

  // type: "hitl_request"
  // toolName, plus:
  requestId?: string;
  details?: string;
  options?: string[];
  command?: string;
  workDir?: string;
  rule?: string;
  method?: string;
  toolCategory?: string;
  filePath?: string;
  riskLevel?: string;
  reason?: string;

  // type: "hitl_auto_approved"
  // requestId, toolName, riskLevel, command, rule

  // type: "done"
  finalOutput?: string;
  stats?: TaskStats;

  // type: "error"
  message?: string;
}

interface TaskStats {
  duration_ms: number;
  tool_calls: number;
  tokens_used?: number;
  hitl_requests: number;
}

type HITLDecision = "approve" | "deny" | "abort";
```

### Subscribing

```ts
client.on("event", (event: AgentEvent) => {
  if (event.type === "text") {
    process.stdout.write(event.content ?? "");
  } else if (event.type === "done") {
    console.log(`Done — ${event.stats?.tool_calls} tool calls`);
  } else if (event.type === "error") {
    console.error(`Error: ${event.message}`);
  }
});
```

## `AgentLoopAgent`

`AgentLoopAgent` implements `acp.Agent` from `@agentclientprotocol/sdk`. It is constructed by the ACP connection factory in `index.ts` and is not typically instantiated directly.

```ts
import { AgentLoopAgent } from "./agent.js";

const agent = new AgentLoopAgent(connection, config);
```

### ACP Methods

| Method | ACP Type | Description |
|---|---|---|
| `initialize(params)` | `acp.InitializeRequest` → `acp.InitializeResponse` | Declares ACP capabilities and agent metadata |
| `newSession(params)` | `acp.NewSessionRequest` → `acp.NewSessionResponse` | Creates a session state entry; returns a new `sessionId` |
| `loadSession(params)` | `acp.LoadSessionRequest` → `acp.LoadSessionResponse` | Loads or restores session history from disk |
| `authenticate(params)` | `acp.AuthenticateRequest` → `acp.AuthenticateResponse` | No-op (returns `{}`) |
| `setSessionMode(params)` | `acp.SetSessionModeRequest` → `acp.SetSessionModeResponse` | No-op (returns `{}`) |
| `cancel(params)` | `acp.CancelNotification` → `void` | Calls `abortTask` on the active client |
| `prompt(params)` | `acp.PromptRequest` → `acp.PromptResponse` | Main prompt handler — connects to server, starts task, streams events |

### Capabilities

The agent advertises:

```ts
agentCapabilities: {
  loadSession: true,
  promptCapabilities: {
    image: false,
    audio: false,
    embeddedContext: true,
  },
}
```

`embeddedContext: true` means Zed can pass `resource_link` and `resource` blocks alongside text in the prompt, which the agent processes via `extractPromptText`.

---

## Prompt Processing (`extractPromptText`)

```ts
import { extractPromptText } from "./prompt.js";

const text = extractPromptText(params.prompt, state.cwd);
```

Converts ACP prompt content blocks to a plain string suitable for the AgentLoop server. Supports:

- **`text` blocks** — concatenated as-is
- **`resource_link` blocks** — converted to `[name] /absolute/path` references
- **`resource` blocks** — same as resource_link
- **Markdown file links** — `[description](relative/path)` in text blocks triggers automatic file embedding (up to 10 files, 100 KB each, 1000 lines each)

When context blocks or markdown file links are present the output is wrapped in `<user_message>` / `<attached_context>` XML. For example, a prompt referencing `[auth.ts](src/auth.ts)` becomes:

```
<user_message>
Fix the bug in [auth.ts](src/auth.ts)
</user_message>

<attached_context>
[auth.ts] /project/src/auth.ts
// (file content embedded here)
</attached_context>
```

## JSON-RPC Wire Format

The client sends and receives newline-delimited JSON:

```ts
// Request (client → server)
{ "jsonrpc": "2.0", "id": 1, "method": "task.start", "params": { ... } }

// Response (server → client)
{ "jsonrpc": "2.0", "id": 1, "result": { "sessionId": "sess-a1b2c3d4" } }

// Notification (server → client, no id)
{ "jsonrpc": "2.0", "method": "event.text", "params": { "sessionId": "sess-a1b2c3d4", "content": "Hello" } }
```

Requests time out after `config.requestTimeout` (default 30 s) with a `Request <method> timed out` error.

<Aside type="note">
  The request ID counter (`nextId`) is per-`AgentLoopClient` instance. Since `AgentLoopAgent` creates a new client per prompt, IDs always start at 1.
</Aside>
