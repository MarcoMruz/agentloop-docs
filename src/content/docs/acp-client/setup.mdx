## Prerequisites

- **Node.js** >= 20
- **AgentLoop server** running and reachable at its Unix socket (default: `~/.local/share/agentloop/agentloop.sock`)
- **Zed IDE** >= 0.150 (with ACP extension support)

Verify the AgentLoop server is up before proceeding:

```bash
echo '{"jsonrpc":"2.0","id":1,"method":"health.check","params":{}}' | \
  socat - UNIX-CONNECT:~/.local/share/agentloop/agentloop.sock
# Expected: {"jsonrpc":"2.0","id":1,"result":{"status":"ok","activeSessions":0}}
```

## Installation

Clone the [agentloop-acp](https://github.com/MarcoMruz/agentloop-acp) repository and install dependencies:

```bash
git clone https://github.com/MarcoMruz/agentloop-acp.git
cd agentloop-acp
npm install
npm run build
```

The compiled entry point is `dist/index.js`. You can also run it during development without building:

```bash
npm run dev
```

<Aside type="note">
  `npm run dev` uses `tsx` to run TypeScript directly. Use it for testing; use `npm run build` for the binary you point Zed at.
</Aside>

## Configuration

### Config File

`agentloop-acp` reads server settings from `~/.config/agentloop/agentloop.yaml`:

```yaml
server:
  socket_path: ~/.local/share/agentloop/agentloop.sock
```

The `socket_path` value expands `~/` automatically. If the file is absent or the key is missing, the default socket path is used.

| Setting | Default | Description |
|---|---|---|
| `server.socket_path` | `~/.local/share/agentloop/agentloop.sock` | Path to the AgentLoop Unix socket |

The request timeout (`30 000 ms`) is currently compile-time only and cannot be overridden via config.

### CLI Override

To point the bridge at a non-default socket without editing the config file:

```bash
node dist/index.js --socket-path /tmp/agentloop-dev.sock
```

This overrides the config file value.

## Configuring Zed IDE

`agentloop-acp` exposes itself as an ACP agent via stdin/stdout. Register it in your Zed settings (`~/.config/zed/settings.json`):

```json
{
  "assistant": {
    "default_model": {
      "provider": "agentloop",
      "model": "agentloop"
    }
  },
  "language_models": {
    "agentloop": {
      "type": "acp",
      "command": "node",
      "args": ["/absolute/path/to/agentloop-acp/dist/index.js"],
      "name": "AgentLoop",
      "provider": "agentloop"
    }
  }
}
```

Replace `/absolute/path/to/agentloop-acp/dist/index.js` with the actual path on your system.

To use a custom socket path in the Zed configuration:

```json
"args": ["/path/to/dist/index.js", "--socket-path", "/tmp/agentloop-dev.sock"]
```

<Aside type="caution">
  Zed launches the ACP process with its working directory set to the project root. All relative file paths in prompts are resolved from there.
</Aside>

## Session Persistence

Conversation history is persisted per ACP session to `~/.local/share/agentloop/acp-sessions/`. Zed can resume a session by passing the same `sessionId` in a `load_session` request. Session files are plain JSON and can be inspected or deleted manually.

## Logging

The bridge writes structured logs to `~/.local/share/agentloop/logs/`. All `console.*` output is redirected to `stderr` to keep `stdout` clean for ACP protocol traffic.

```bash
# Tail logs while using Zed
tail -f ~/.local/share/agentloop/logs/*.log
```

Set `NODE_ENV=development` to enable `debug`-level log output and console logging:

```bash
NODE_ENV=development node dist/index.js
```

## Verifying the Setup

After configuring Zed, open the Assistant panel. The ACP handshake is automatic. Check the logs for the startup message:

```
AgentLoop ACP Bridge started successfully
```

And for each user turn:

```
[ACP] Prompt request received
[AgentLoop] Connected to AgentLoop server
[AgentLoop] Task started: sess-xxxxxxxx
```

If the connection to the Go server fails you will see a `Connect failed` error in the Zed Assistant panel and in the logs.
